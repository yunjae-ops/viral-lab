# SPEC.md — Viral Lab 기능 사양

## 0. 한 줄 요약

Threads 바이럴 콘텐츠 업무용 내부 웹도구. Next.js 한 프로젝트 안에 두 페이지.

- `/review` — 내가 쓴 Threads 초안을 내 원칙으로 평가
- `/scout` — Threads에서 새 레퍼런스를 수집 (Review 완성 후에만 개발)

---

## 1. `/review` 사양

### 1.1 사용자 시나리오

1. 사용자가 자신이 관리 중인 Excel 파일을 브라우저에서 업로드한다.
2. 도구가 Excel의 실제 Header 행을 자동으로 찾고, 몇 행이 감지됐는지 사용자에게 보여준다.
3. 사용자가 "분석 시작" 버튼을 누른다.
4. 도구가 각 행(콘텐츠 초안)에 대해 Claude로 Core Grade + Diagnostic을 계산한다.
5. 진행률이 실시간으로 보인다 (예: `47 / 120`).
6. 모두 끝나면 표에 결과가 표시되고 Portfolio Analysis(전체 통계)가 상단 카드로 나타난다.
7. 사용자가 "결과 다운로드" 버튼을 누르면 원본을 건드리지 않고 `..._ANALYZED_YYYYMMDD_HHmm.xlsx` 파일이 만들어진다.

### 1.2 입력 Excel 형식

- 일반적인 "첫 행 = Header" 형식이 아니다. 앞쪽에 빈 행 또는 안내문이 있을 수 있다.
- **필수 Header (반드시 포함):**
  - `순서`
  - `/제목` — Threads 레퍼런스 URL
  - `리뷰내용` — 사용자가 작성한 콘텐츠 초안
  - `이미지 파일명`
- **선택 Header (있으면 사용):**
  - `레퍼런스 원문` — 있으면 레퍼런스 vs 초안 비교, 없으면 초안 단독 평가
- Header 자동 감지 규칙:
  - 처음 20행을 훑는다.
  - 필수 Header 4개(정확 일치)를 모두 포함하는 첫 행을 Header 행으로 확정.
  - 못 찾으면 에러 메시지: "Header를 찾지 못했습니다. 필수 컬럼: 순서, /제목, 리뷰내용, 이미지 파일명".

### 1.3 Core Grade (핵심 판정)

각 콘텐츠 초안 1개에 대해 4개 Gate를 통과했는지 판정.

| # | Gate 이름 | 통과 기준 |
|---|-----------|-----------|
| G1 | 본문 완결성 | 질문/댓글에 의존하지 않고 본문에서 내용이 완결되는가 |
| G2 | 발견/전환 | 발견 또는 전환의 순간이 존재하는가 |
| G3 | 서사 완결 | 서사가 본문 안에서 완결되는가 |
| G4 | 결과·원인 구조성 | 결과의 원인이 구체적이고 구조적으로 활용 가능한가 |

**등급 계산 (Phase 3에서 확정, 초기 제안):**
- 4개 통과 → **A**
- 3개 통과 → **B**
- 2개 통과 → **C**  *(사용자 확정 필요)*
- 0–1개 통과 → **D**  *(사용자 확정 필요)*

각 Gate는 `pass | fail`과 짧은 근거 문장(evidence) 1개를 함께 반환.

### 1.4 Diagnostic (참고 지표, Core Grade와 분리)

Core Grade와 절대 섞지 않는다. UI에서도 별도 섹션.

- Hook Code A–M 분류 (13개 카테고리)  *→ A–M 정의 확정 필요, DECISIONS.md D-004 참고*
- 감정 태도 분류 (예: 담담 / 확신 / 놀람 / 냉소 / 공감 등, 목록 확정 필요)
- 화자 인칭·관계 (예: 나 / 우리 / 관찰자 / 전문가 / 소비자 등)
- 정보 공개 방식 (예: 직접 서술 / 대화 재현 / 리스트 / Q&A 등)
- 리스트형 항목의 문법적 균질성 (해당 시 pass/fail + 근거)
- 제품·판매 메시지 비중 (0–100% 추정)
- 레퍼런스와의 과도한 문장/디테일 유사성 (레퍼런스 원문이 있을 때만; 유사 문장 인용)
- 사실 검증이 필요한 건강/효능 주장 목록 (문자열 배열)
- 수정이 필요한 핵심 포인트 (문자열 배열, 최대 3개)

### 1.5 Portfolio Analysis (Excel 전체)

전체 행이 분석된 뒤 1회 계산.

- A–M 코드별 사용 개수(막대)
- 감정 태도 분포(막대)
- 화자 인칭 분포(막대)
- 정보 공개 방식 분포(막대)
- 과사용 경고: 어떤 카테고리가 상위 임계치(예: 40% 초과)이면 자동 경고
- 다음 소재에서 비어 있는 방향 추천 (자유서술 텍스트, Claude가 생성)

> **단순화 제안 (DECISIONS D-002 참조):**
> 분포·개수·경고까지는 코드로 계산(집계)한다. Claude 호출은 "다음 소재 추천" 자유서술 부분에만 사용한다.
> 이렇게 하면 통계는 항상 정확하고 재현 가능하며, AI 비용도 1회로 끝난다.

### 1.6 결과 저장 방식

- **화면:** 표 + 상단 Portfolio 카드.
- **다운로드:** 원본 파일과 같은 폴더 개념이 아니라, 브라우저 다운로드로 새 xlsx 파일 제공.
  - 파일명: `{원본이름}_ANALYZED_{YYYYMMDD_HHmm}.xlsx`
  - 원본 시트 유지 + 다음 시트 추가:
    - `Analysis` — 원본 행 + Core Grade + 각 Gate 결과 + Diagnostic 요약 컬럼들
    - `Portfolio` — 집계표 + AI 요약 문단

### 1.7 성능·비용

- 초기 동시성 = 3 (Claude 호출 병렬 3개까지).
- 분석 시작 전 다이얼로그: "총 N건, 예상 호출 건수 N+1건(포트폴리오 1회 포함). 계속?"
- 실패한 행은 표시만 하고 나머지는 계속 진행. 실패한 행만 재시도 버튼 제공.

### 1.8 인증

- 초기: 인증 없음. 배포 URL을 아는 사람만 접근한다는 전제.
- **단순화 제안 (D-005):** Vercel의 Password Protection(팀 요금제 이상) 또는 매우 얇은 자체 세션 하나. 초보자는 우선 URL 비공개로 시작하고, 실제 유출 위험이 생기면 그때 붙인다.

## 2. `/scout` 사양 (Review 완성 후에만 개발)

### 2.1 사용자 시나리오

1. 사용자가 검색 키워드와 옵션(TOP/RECENT, 기간, 최대 개수)을 입력한다.
2. "수집 실행" 버튼을 누른다 — **자동 스케줄 없음, 수동 트리거만.**
3. 도구가 Threads 공식 keyword search API를 호출해 결과를 받아온다.
4. 기존에 저장된 것과 중복 제거 후 Supabase에 upsert.
5. 결과 테이블: `text`, `permalink`, `username`, `timestamp`, 수집 태그.
6. 각 행 옆에 "원문 보기"(permalink 새 창) + "원문 붙여넣기"(textarea, 자동 스크래핑 실패 대비 수동 fallback).
7. 사용자가 원하면 특정 행을 Review 형식으로 밀어넣을 수 있다(선택 기능, Phase 후반).

### 2.2 데이터 저장

- Supabase 테이블 `scout_items` (스키마는 DATA_CONTRACT.md 참조).
- 중복 판정 키: `permalink` (unique).

### 2.3 자동화

- 자동 수집은 마지막 Phase에서만.
- 방식: Vercel Cron Jobs(플랫폼 내장 스케줄러) 1개.
- 자동 수집 실패 시 조용히 실패하지 않고 관리자용 로그 페이지에 남긴다.

### 2.4 스크래핑 정책

- 공식 API 결과 필드만으로 최대한 처리한다.
- 임의 URL의 본문 크롤링을 만들지 않는다. 필요하면 사용자가 원문을 붙여넣는다.
